<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| parsed signal to execution rules | A validated `LLMSignal` proposes an action but deterministic execution rules decide whether it becomes an order intent. |
| held position and price to risk net | Position/price inputs trigger LLM-independent risk exits before any signal-derived action. |
| environment to Settings | Operator-configured thresholds and caps enter the runtime through typed settings. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-03 | Elevation of Privilege | `trading_bot.execution` | high | mitigate | Risk is evaluated before LLM action and risk override is represented in `ExecutionResult`/`CycleAuditEvent` per D-07. |
| T-02-04 | Tampering | sizing and thresholds | high | mitigate | BUY/SELL thresholds, cash fraction, and max cap are typed settings and covered by execution tests. |
| T-02-05 | Denial of Service | daily-loss kill switch | medium | mitigate | Kill switch blocks new BUY actions only; SELLs and risk exits remain allowed per D-08. |
| T-02-06 | Repudiation | override/audit result | medium | mitigate | Execution result records the final action, risk override reason, and no-order reasons for tests to assert. |
| T-02-SC | Tampering | package installs | high | mitigate | No package-manager install tasks exist in this plan; use existing `pydantic-settings`, stdlib dataclasses/enums, and pytest. |
</threat_model>
