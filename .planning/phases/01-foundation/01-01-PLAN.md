<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator environment to settings | Secrets and mode flags cross from `.env`/environment into typed runtime configuration. |
| package registry to local environment | SUS package metadata from PyPI influences dependency lock-in/install. |
| repository to future runtime | Tracked templates and package metadata define future startup behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `.env` / `.env.example` | high | mitigate | `.gitignore` must ignore `.env`; `.env.example` must contain placeholders only. |
| T-01-02 | Tampering | KIS mode env names | high | mitigate | `.env.example` exposes grouped `KIS_MOCK__*` and `KIS_REAL__*` variables selected by `TRADING_MODE`, not independent active fields. |
| T-01-03 | Elevation of Privilege | real trading confirmation | high | mitigate | Template includes `CONFIRM_REAL_TRADING` and later config rejects real mode without the explicit confirmation value. |
| T-01-SC | Tampering | PyPI dependency install/lock-in | high | mitigate | Blocking human checkpoint verifies `pydantic-settings`, `pydantic`, and `pytest` before dependency declaration or install. |
</threat_model>
