<objective>
Deliver the two side-channel sinks the operable cycle needs: a two-table SQLite audit writer (OPS-02) that persists every per-ticker decision consuming the frozen `CycleAuditEvent` with a correlation id to the Phase 4 structlog line, and a fail-soft Discord `Notifier` adapter (OPS-03) that pushes one consolidated per-run summary and never blocks trading.

Purpose: The audit store is the reviewable system of record (repudiation defense); the notifier is a best-effort operator push. Both are strictly side channels — neither may change the domain types, block the cycle, or leak secrets. This plan has zero file overlap with the order-path plan (05-02), so it runs in the same wave.
Output: `trading_bot/sqlite_audit.py`, `trading_bot/notifier.py`, and their offline tests.
</objective>
