<objective>
Build the idempotent, reconciled real-money order path (EXEC-04) by extending the existing Phase 3 direct-REST KIS layer — NOT adopting `python-kis` (D-05). A new `kis_order.py` adapter reuses the shared `KisTokenManager` to POST order-cash and query fills/balance; a new `KISBroker` satisfies the existing `Broker` Protocol and implements query-before-POST reconciliation, single-shot POST (never retried), and partial-fill readback.

Purpose: The order POST is the single most dangerous operation in the system. This plan encodes the defense-in-depth idempotency (deterministic client tag + reconcile-against-broker-truth) and the "never blind-retry a POST" invariant that EXEC-04 / D-06 demand, plus limit-only orders snapped to KRX tick bands and a market-hours/stale pre-flight guard (D-08).
Output: `trading_bot/kis_order.py`, `trading_bot/kis_broker.py`, and their offline tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bot → KIS order API | Non-idempotent real-money POST crosses here; the highest-stakes boundary in the system |
| KIS API → bot | KIS responses (fills, balance) are untrusted input that drives position/state |
| config → adapter | TR_ID/domain selection crosses from atomic active_kis into the order path |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-04 | Tampering / financial DoS | order-cash POST retry | critical | mitigate | POST is single-shot, physically un-retryable; any resend re-queries broker truth first (D-06); test asserts POST attempt count == 1 |
| T-05-05 | Elevation of Privilege | mock TR_ID against real domain (or vice versa) | high | mitigate | TR_ID derived from atomic active_kis.tr_id_profile, never hard-coded; loud startup banner; layered gate (Plan 04) |
| T-05-06 | Spoofing / Tampering | malformed/hostile KIS response treated as a real fill | high | mitigate | Validate rt_cd + numeric fields before trusting fills/positions (mirror kis_quote); fail safe on malformed (V5) |
| T-05-07 | Tampering | off-tick ORD_UNPR rejected by KRX | medium | mitigate | snap_to_tick to the 2023-reform band before POST (D-08) |
| T-05-08 | Information Disclosure | appkey/secret/token leak into logs | high | mitigate | Reuse KisTokenManager redaction; no secret in __repr__; assert_no_secret_leaked in tests |
| T-05-09 | Tampering | second KIS token flow opened in the order path | high | mitigate | kis_order/kis_broker consume the injected shared KisTokenManager only; factory raises if none supplied (D-05/D-14) |
</threat_model>
