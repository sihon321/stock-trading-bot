<objective>
Build the idempotent, reconciled real-money order path (EXEC-04) by extending the existing Phase 3 direct-REST KIS layer — NOT adopting `python-kis` (D-05). A new `kis_order.py` adapter reuses the shared `KisTokenManager` to POST order-cash and query fills/balance; a new `KISBroker` satisfies the existing `Broker` Protocol and implements query-before-POST reconciliation, single-shot POST (never retried), and partial-fill readback.

Purpose: The order POST is the single most dangerous operation in the system. This plan encodes the defense-in-depth idempotency (deterministic client tag + reconcile-against-broker-truth) and the "never blind-retry a POST" invariant that EXEC-04 / D-06 demand, plus limit-only orders snapped to KRX tick bands and a market-hours/stale pre-flight guard (D-08). The order surface is split across two tasks (query/validation build first, then the order-POST build) so the highest-correctness code is not folded into one over-dense action, and a blocking human-verify gate confirms the `[ASSUMED]` KIS fill-field spellings against the portal before the fill-readback parser trusts them.
Output: `trading_bot/kis_order.py`, `trading_bot/kis_broker.py`, and their offline tests.
</objective>
